# v0.5：皮肤与丝袜分层

## 原因与方案

v0.4 已经使用独立袜壳，并没有修改身体顶点，但仍有两个视觉耦合：袜壳沿用了包含肤色的整张颜色贴图，抓取时会把肤色拉长；身体着色器又根据抓取位置与拉伸量局部改色。这容易造成“把腿也一起拉动”的观感。

本次不重新雕刻腿型，也不改变原模型坐标。采用三层结构：

1. **固定皮肤显示层**：原始身体几何的独立属性副本。交互模式使用静态肤色重建材质；皮肤着色器没有抓取位置、力度、袜类或拉伸量输入。
2. **只读碰撞代理**：从默认 18 万面几何复制的静态三角面与 BVH。模拟只查询，不修改它。切换 150 万面显示时仍复用此代理，避免重建高成本碰撞树。
3. **动态丝袜层**：独立的几何、位置、法线、索引和材质。只有该层接收射线抓取及物理更新。UV 接缝处的重复位置使用一致法线，减少拉伸开缝。

`garment-layers.js` 统一创建并持有这些对象。输入模型、皮肤、碰撞代理与动态丝袜不共享可写的位置缓冲区。

## 材质如何分离

`layer-materials.js` 创建三份独立材质：

- **固定皮肤**：只按原位置与低频纹理近似重建肤色；抓取与换袜都不改变它。
- **织物**：程序化颜色、织纹、透明孔洞及光泽。原织纹选项只从源图提取标量线纹遮罩，不再把源图 RGB 肤色绘制到移动袜层。
- **原模对照**：独立保留原颜色与粗糙度贴图，暂停丝袜交互时用于对照。它不作为可拉伸的袜材质。

原文件没有真正的裸肤纹理，因此分层后的皮肤仍是近似重建。这是渲染和物理层的明确分离，不是从有袜贴图无损恢复真实裸肤。

## 碰撞和回弹

保留弹簧阻尼与局部影响权重，在此基础上增加静态皮肤三角形查询：

- BVH 加速最近三角形搜索和线段扫掠。
- 每次较大移动检查上一位置到候选位置的线段，阻止顶点从皮肤一侧穿到另一侧，即便终点已经到达对侧外部。
- 接触时按最近表面的实际距离维持 `0.014` 个显示单位的间隙，移除朝向皮肤的速度。
- 在三角形边缘使用最近点的欧氏距离，而不是把面法线投影误当作实际间隙，避免产生接触粘滞。
- 初始袜层迭代建立稳定的贴肤静止位置，松手回到此位置；重置只恢复袜层缓冲区。

该方案仍是局部弹性视觉模拟，没有完整织物有限元、纱线约束或布料自碰撞。碰撞依赖提供网格的表面质量和朝向；开放边界、非流形或自相交区域不能保证任意轨迹都无穿插。

## 验证入口

界面新增 **皮肤 + 丝袜 / 只看皮肤 / 只看丝袜**。只看皮肤时暂停抓取；只看丝袜时保留隐形碰撞代理，便于单独观察袜层的拉起和回弹。

运行 `node check-layers.cjs` 检查：

- 两层的几何、位置、索引与材质独立；源数据及碰撞代理也不与显示层共享可写缓冲区。
- 实际模型拉伸、松手、重置后，皮肤的位置、法线、索引及源几何逐元素不变。
- 右腿拉伸不影响左腿，布料有明显抬起，并能回到独立静止位置。
- 闭合测试体的线段穿越和切向接触；实际模型上被拉起顶点与附近皮肤表面的接触。
- 皮肤着色器不含抓取控制输入；袜层不使用整张原图作为 RGB；完整精度替换仍保持缓冲区隔离。

这些是数据、几何和材质构建检查，不是 GPU 像素验收。当前会话没有可用的浏览器自动化工具，因此本次不声称已完成浏览器视觉验证。
